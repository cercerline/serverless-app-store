# promo/animation.html — 20 秒宣传动画

一个**单文件、零依赖、离线可跑**的循环动画，用来吸引「用 AI 做了 app 的人」把作品传到
[xiaokaiqi.website](https://xiaokaiqi.website)。

双击 `animation.html` 即可用浏览器打开，按「播放动画」开始。

## 怎么用

| 操作 | 说明 |
|---|---|
| 双击文件 | 直接打开，不需要服务器、不需要联网 |
| 空格 | 暂停 / 继续（暂停后可从容截图） |
| R | 从头重播 |
| F | 全屏（录屏建议用全屏） |
| 鼠标不动 2.6 秒 | 底部控制栏自动变淡，画面干净，适合录屏 |

动画每 20 秒无缝循环一次，所以任何时候开始录屏都能录到完整内容。

## 6 个镜头

| 时间 | 内容 | 屏幕上的字 |
|---|---|---|
| 0–3s | 让 AI 写代码，做出一个 app | 你刚刚用 AI / 做出了一个 app |
| 3–6s | 痛点：装不到别人手机上 | 但这个 app，只有你自己能装 |
| 6–8s | 商店出现，手机被吸进上传口 | 小凯奇 AI 应用商店 / 把它传上来，让别人也能下载 |
| 8–13.4s | 10 个文件飞进上传口，计数递增 | 把做好的 app 传上来 → 上传成功 · 自动生成下载页 |
| 13.4–17s | 三个卖点卡片 | 为什么值得传上来 |
| 17–20s | 行动号召 + **可扫描的二维码** | 把你的作品，放到这里 / 上传我的应用 → |

二维码指向 `https://xiaokaiqi.website/upload`（一个**稳定短路径**，站点会重定向到注册/上传流程），
不是装饰图，是页内自己生成的真二维码，可以真扫。

### 为什么用 /upload 而不是 /register

视频一旦录完，二维码就**永久固定**在片子里了，改不了。所以片子里的地址必须是
「以后也不用改」的那种：

- `/upload` 由站点重定向到真正的上传流程。哪天上传流程换了位置（`/register` → `/submit`、
  换表单服务、换域名），**改重定向那一行就行，不用重录视频**。
  实现见 [src/app/upload/page.tsx](../../src/app/upload/page.tsx)。
- 这条重定向用的是**临时重定向**，不是 `permanentRedirect`。308 会被浏览器长期缓存，
  一旦有人扫过一次，之后你再改目标他也到不了新地址 —— 正好毁掉这条路由存在的意义。
- 地址越短，二维码版本越低、格子越大、越好扫。`/upload`（v3，29×29）比带一堆 `utm_` 参数的
  链接可靠得多；实测把一个上百字符的长链接塞进来会升到 v5（37×37），格子明显变小。
- **别往这个路径后面加追踪参数**：会推高二维码版本、缩小格子，实际扫码成功率会下降。
  要分渠道统计，请在落地页里做，不要做进二维码。

### 临时换一次落地页（不用改代码）

想为某一条视频单独指到别的地址，直接在地址栏加 `?qr=`：

```
animation.html?qr=https://example.com/anything
```

二维码会在加载时按这个地址重新生成，画面下方的网址文字也会跟着变。
只接受 `http` / `https`，其他协议会被忽略并回退到默认值。

## 想改文案 / 改二维码地址

都在同一个 `<script>` 里，改完存盘刷新即可：

- **二维码地址**：见上一节 —— 临时换用 `?qr=`，长期换用 `SITE_ORIGIN + "/upload"`，
  或者改站点那条重定向（推荐，这样已录好的视频也不用重录）。
- **镜头文案**：搜对应函数名 —— `sceneHook` / `scenePain` / `scenePortal` /
  `sceneUpload` / `sceneWhy` / `sceneCta`。
- **每个镜头的时长**：搜 `const SCENES`，改 `start` 的秒数（总时长由 `DURATION` 控制）。
- **上传口位置 / 二维码位置**：搜 `const LAYOUT`。

配色沿用站点本身（`--color-brand-500: #14b8a6`、`--color-ink-950: #070b14`），
和线上页面是同一套视觉。

## 验证

`verify/` 里是配套的校验脚本，全部无第三方依赖，Node 20+ 直接跑：

```bash
cd promo/verify

node qr-verify.mjs        # 独立解码器复检二维码编码器
node qr-embed-check.mjs   # 确认 HTML 内嵌编码器与参考实现逐格一致
node anim-smoke.mjs       # 无头跑完 20 秒全部帧，查运行期错误
node qr-png.mjs           # 把二维码面板导出成 ../qr-preview.png，肉眼看一眼
```

三者的结论：

1. **`qr-verify.mjs`** 用「扫描器视角」把符号读回来：读格式信息 → 反掩码 → 按之字形取码字
   → 反交织 → 校验 Reed-Solomon 校验子 → 还原原文。覆盖 v3-M、v3-L、v4-M、v4-Q、v3-H、
   **v5-M**（共 6 例，含多 RS 块），全部 `format=canonical rs=valid payload=recovered`。
   这比「看起来像个二维码」强得多——它证明符号真的能被解码。
2. **`qr-embed-check.mjs`** 防止 HTML 里的那份编码器被改坏：逐格比对内嵌版本与参考版本。
3. **`anim-smoke.mjs`** 用桩 canvas 跑完 2402 帧，检查引用错误、`NaN`/`Infinity` 坐标、
   越界的 `globalAlpha` 与 `lineWidth`。它还会打印当前二维码指向和版本。
   想测 `?qr=` 覆盖效果：`QR_TEST_URL="file:///x.html?qr=https://a.example/b" node anim-smoke.mjs`

> 注：`qr-embedded.mjs` 和 `qr-panel.pbm` 是中间产物，可随时删除、也会被重新生成。

## 没做 / 已知取舍

- **没有配乐和音效**：保持零依赖、零版权风险。要加音乐，录屏时用剪辑软件配即可。
- **没有导出 MP4**：按需要给了可在浏览器播放并录屏的版本。若要直接出视频文件，
  用 OBS / 系统录屏全屏录 20 秒即可，画面本身就是 16:9（1600×900）。
- **画面按 16:9 设计**：窗口比例不符时自动等比缩放并居中，不会变形。
- **二维码带 4 模块静区**（规范要求的下限），模块边长取整数像素，边缘不糊，方便扫。
- **二维码在片子里是静态的**：0.9 秒的「模块由内向外浮现」动画结束后就完全静止，
  最后约 1.85 秒画面里没有任何抖动/闪烁/缩放，直接截这一帧也能扫。
  静止下来之后刻意不做任何逐帧效果 —— 逐帧噪点会显著降低实机扫码成功率。
